# RAG 应用评测平台

一个面向 RAG 应用的自动化评测平台：**量化**回答质量、**归因**失败环节、**验证**优化效果。

被评测对象是一个已存在的 Java RAG 知识库 `sk-knowledge`（Spring Boot + Spring AI + Weaviate）。
本平台通过 HTTP 观测它，不做侵入式改造。

## 它解决什么问题

做完一个 RAG 系统之后，最常见的困境是"我不知道它到底好不好"——
只能凭感觉问几个问题，改完 prompt 也不知道是变好还是变坏。本项目要交付三件事：

1. **量化**：一套可比较的分数，而不是体感。
2. **归因**：把失败定位到具体环节——是没召回到、召回到了但没答对、还是幻觉。
3. **验证**：改动前后的分数可对比，能证明优化真的有效。

## 与通用评测框架的差异

RAGAS 之类的框架主要做**结果层**评分（最终答案对不对）。本项目做**结果层 + 过程层**双层评测，
过程层回答的是"召回了哪些片段、期望条文排在第几位、答案有没有忠于召回内容"——
这需要能看到检索环节的明细，是通用框架做不到的。


## 当前基线（2026-09-27，52 条）

朴素模式，一轮约 2 分 47 秒（平均 2.7 秒/条）。

| 层 | 指标 | 平均分 | 通过率 | 适用样本 |
| --- | --- | --- | --- | --- |
| process | `retrieval_hit` | 0.56 | 86% | 44 |
| process | `citation_support` | 0.94 | 90% | 29 |
| outcome | `semantic_similarity` | 0.87 | 95% | 44 |
| outcome | `points_hit` | 0.88 | 77% | 44 |
| outcome | `refusal` | 0.94 | 94% | 52 |

**全部通过 31/52（60%）**，落在 `project.md` §4 要求的 40–70% 区间内。
失败归因：召回到了但没答对 11 · 幻觉 7 · 该拒答没拒答 3。**调用失败 0 条。**

两条容易看错的口径（详见 `project.md` §4）：

- **「不适用」不计入通过率**：拒答题在 `retrieval_hit` 等指标上本就无从判定，
  把它们当"通过"计入会让数字虚高（实测 88% → 86%）。
  「适用样本」列才是真正参与计算的条目数——`citation_support` 只有 29 条适用，
  因为答案没引用条文号时该指标无从判定。
- **调用失败不计入通过率**：那是平台侧故障（网络 / 上游 5xx / 流被掐断），与模型能力无关。

1. **多轮没有优势**：6 条多轮用例，朴素 5/6、Agentic 5/6 —— **打平**。

### 五个页面

| 页面 | 路径 | 做什么 |
| --- | --- | --- |
| 评测运行 | `/runs` | 运行历史、发起一轮新评测（带实时进度） |
| 评测报告 | `/runs/:runId` | 分层得分、题型分解、失败归因、逐条结果 |
| Trace 详情 | `/runs/:runId/trace/:caseId` | 单条用例的评分、模型回答、**召回了哪些片段** |
| Run 对比 | `/compare` | 两次运行的逐条差异 |
| 评测集 | `/datasets` | 浏览条目（含轮次）、一键校验条文号与要点 |

> 注意：前端在 `main.js` 里全局注册了 Naive UI（`app.use(naive)`）。
> 各页面大量使用 `n-*` 组件，**未注册的组件不会报错**，
> 只会把子内容内联渲染出来（表现为"弹窗内容摊在页面上、表格空白"），
> 排查时很难联想到这个问题。

## 已知的量化事实

被评测模型的延迟差异极大，且这**曾是**整个项目最大的时间成本项：

| 配置 | 单次耗时 | completion tokens |
| --- | --- | --- |
| `Qwen/Qwen3-8B`（推理模型，**已弃用**） | 15s ~ 94s（波动大） | 362 ~ 481 |
| `Qwen/Qwen2.5-7B-Instruct` | **1s** | 33 |
| `deepseek-chat`（**当前使用**） | 端到端一轮 **3.8s** | —— |

端到端一轮完整 RAG 问答（含检索与历史上下文）：`Qwen/Qwen3-8B` 实测 **211 秒**、
`deepseek-chat` **3.8 秒**。换模型把 Phase 3 的评测迭代从"一天只能跑一两轮"
变成"随时可跑"，是项目可行性的关键转折。
详见 `project.md` 第 4 节末尾的实测表格与优化杠杆清单。
